# PLCの値を「見える化」する：STAMPLC_D100_TREND

FX5UのD100を読み、STAMPLCのLCDに折れ線グラフで表示します。PLCへの書き込みは行いません。

配線・PLC設定・ライブラリは[共通README](../README.md)を参照してください。

## 画面と操作

- 上段：現在のD100。符号付き16bit整数として表示します。
- 中段：直近120回の読み取り結果。左が古く、右が新しい値です。
- 下段：表示中の最小値・最大値・サンプル数。
- KEY1：履歴を消去します。D100の値は変更しません。

履歴は右端から増え、120回に達すると古い値を捨てながら左へ流れます。履歴はRAMだけに保持するため、電源OFFやリセットでも消えます。KEY1で消去した後は、次の読み取り成功から記録を再開します。KEY2・KEY3は使用しません。

グラフの縦軸は表示中の最小値・最大値に自動で合わせます。同じ値が続くと中央の水平線になります。縦軸が変わるため、変化の大きさは下段のMIN/MAXも合わせて確認してください。

中央の灰色線はグラフの高さの中央を示し、値の0を示す線ではありません。

## グラフの幅と取得周期

| 項目 | 現在の設定 |
| --- | --- |
| LCD | 横240×縦135ピクセル |
| グラフ枠 | 横240×縦78ピクセル |
| 履歴数 | 直近120回の成功した読み取り |
| 次の要求までの待ち時間 | 読み取り結果の表示後、200ms |
| 通常時の取得間隔 | 通信・描画の処理時間＋200ms |
| グラフ全体の時間の目安 | 履歴が満杯のとき約24秒＋通信・描画にかかる時間 |

固定の200ms周期ではありません。120点の最初と最後の間には119区間あるため、待ち時間だけなら23.8秒です。横軸はサンプル順で、厳密な時間軸ではありません。通信異常で取得できなかった時間も横幅には反映しません。

周期を変更する箇所は`src/main.cpp`の`onRead()`末尾です。

```cpp
nextRead = millis() + 200;
```

履歴数は`HISTORY_SIZE = 120`で指定しています。変更する場合は、LCDの`/120 samples`という表示も合わせて変更してください。

## 通信異常時

読み取り成功は緑LEDを約150ms点灯します。通信異常では上段を`COMM Error`に切り替え、赤LEDを点灯し、3秒後に再試行します。異常前のグラフは残しますが、失敗した読み取りは追加しません。復帰すると履歴の続きに追加するため、通信が途切れた時間はグラフの横幅に反映されません。必要ならKEY1で履歴を消してください。

赤LEDは次の読み取り成功で緑に戻ります。読み取り専用なので青LEDは使用しません。USBシリアル（115200bps）には読み取った値とエラーの詳細を出力します。

自動復帰の条件・遅延応答の制約は[元のD100モニター](../STAMPLC_D100_MONITOR/README.md)と同じです。厳密な計測時刻を保証する記録計ではありません。

## コードの見どころ

非同期読み取りの完了時に値を120要素のリングバッファへ保存し、M5Stack公式ライブラリの`drawLine()`で描画します。満杯になると古い値から上書きします。通信待ち中もKEY1を処理します。グラフ用ライブラリや追加のRTOSタスクは不要です。

ソース：[main.cpp](src/main.cpp)。
