# STAMPLC_DEVICE_EDITOR：デバイスの値を確認・変更する

配線・FX5Uの設定・使用ライブラリは[共通README](../README.md)を参照してください。

KEY1～3でFX5Uのデバイス・番地・値を操作するサンプルです。公式M5StamPLCライブラリを使用し、起動直後はDEVICEモードでD100を読み取ります。デバイス・番地の変更だけでは書き込みません。

## キー操作

| キー | 操作 |
| --- | --- |
| KEY1 / BtnA | DEVICE → ADDRESS → VALUE → DEVICE の順にモード切替 |
| KEY2 / BtnB | 選択モードの項目を1つ増やす |
| KEY3 / BtnC | 選択モードの項目を1つ減らす |

1回押すと1段階です。長押し連続操作はありません。KEY2とKEY3の同時押しは変更しません。

- DEVICE：指定順にデバイスを切替。先頭と末尾は循環し、デバイスごとに最後に選んだ番地を復元します。初期値はDが100、他は0です。番地の記憶は起動中だけで、電源OFFやリセットで初期値に戻ります。
- ADDRESS：番地を1点ずつ増減。0未満にはなりません。
- VALUE：読み取った値を1増減し、確定キーなしでPLCへ書き込みます。ビットはUpで1、Downで0です。上下限で停止し、値は周回しません。

例えばD100からMへ切り替えてM20を選んだ後、Dへ戻すとD100、Mへ戻すとM20を表示します。記憶するのは番地で、値は切り替えるたびにPLCから読み直します。

## デバイスと値の型

選択順：X、Y、M、L、F、B、D、W、R、SM、SD、SB、SW、Z、LZ、TS、TC、TN、STS、STC、STN、CS、CC、CN、LCS、LCC、LCN。

| 型 | デバイス | 値の範囲 |
| --- | --- | --- |
| ビット | X,Y,M,L,F,B,SM,SB,TS,TC,STS,STC,CS,CC,LCS,LCC | 0～1 |
| 符号付きWORD | D,W,R,SD,SW,Z,TN,STN,CN | −32768～32767 |
| 符号付きDWORD | LZ,LCN | −2147483648～2147483647 |

WORDの符号変換はライブラリの非同期符号付き読み取りで行います。LZ・LCNはDWORDのランダム読み書きを使います。LCNの番地を増やすと次のロングカウンターを選びます。

番地表示はX/Yが8進、B/W/SB/SWが16進、他は10進です。LCDの括弧内に基数を示します。例えばX7の次はX10、WFの次はW10です。通信APIへは実際の数値インデックスを渡します。UIの上限0xFFFFFFは通信形式の表現範囲であり、PLCの使用可能範囲ではありません。機種・デバイス設定・特殊デバイスの属性で読み書きできない番地はPLCエラーになります。

## 表示と即時書き込み

```text
MODE: VALUE
D100 (10)
VALUE: -66
OK
```

値変更を受け付けると表示値を変え、`Writing...`を表示して送信します。通信中なら、その通信が終わった直後に送ります。無制限に要求を重ねず、送信中を含め最大8件を順番に処理します。満杯では追加操作を受け付けず`BUSY / queue full`と表示します。未完了の書き込みがある間はデバイス・番地の変更を受け付けません。

最後の書き込み後は読み返してPLCの実際の値を表示します。ラダーなどが同じデバイスを書き換えている場合、値が元に戻ることがあります。押した値が永続することを保証する操作ではありません。

デバイス・番地変更後は古い値を消して`---`を表示し、新しい値を読み取るまで書き込みできません。変更前に開始した読み取りの完了結果は破棄します。通信異常後に線上へ遅れて届く応答については、後述の制約があります。

USBシリアル（115200bps）には読み取り結果、書き込み成功、エラーの詳細を出力します。ログの`index`は10進数の番地です。

## RGB LED

| 色 | 意味 |
| --- | --- |
| 緑 | 読み取り成功。約150ms点灯 |
| 青 | 書き込み成功。約150ms点灯 |
| 赤 | 通信異常。選択中のデバイスの読み取りに成功するまで点灯 |

青の点灯中に読み取りが成功しても、青を約150ms保持します。通信異常は青の点灯中でも即座に赤へ切り替えます。LEDは送受信中ではなく、通信結果を示します。

## 通信とエラー

接続条件は[共通README](../README.md)の設定を使用します。

通常は読み取り完了から500ms待って次の読み取りを開始します。デバイス・番地の変更時と、最後の書き込み完了後は待たずに読み取ります。通信中はその完了を待ってから次の要求を送ります。通信の応答待ち中もLCDとボタン更新はloop内で続けます。

通信異常時は`COMM Error`と赤LEDを表示し、未完了の書き込みキューを破棄します。3秒後にUARTを再初期化し、選択中のデバイスを読み直します。初回のUART初期化に失敗した場合も再試行します。本体のリセットは不要で、選択デバイスと記憶した番地は保持します。

復旧待ち中もデバイス・番地を選べますが、値変更は読み取り成功まで受け付けません。書き込みがPLCで実行されたか不明な場合もあるため、失敗した書き込みは自動再送しません。成功すると実際に読み取った値を表示し、通常の操作へ戻ります。

再試行に失敗した場合も、エラー発生から3秒待って再試行します。ボタン操作でこの待ち時間が短縮されることはありません。存在しない番地などでPLCエラーが続く場合は、DEVICEまたはADDRESSモードで読み取り可能なデバイス・番地を選んでください。

3秒は再試行間隔で、遅延応答がなくなる保証値ではありません。形式5では古い応答を新しい要求への応答と区別できない場合があります。この自動復帰は、再試行時に前の応答が届かない1対1接続を前提とします。遅延があり得る設備では最大応答時間を確認して`RETRY_INTERVAL_MS`を調整するか、通信路の復旧確認後に再開する方式に変更してください。

## 確認事項

上のデバイス一覧はサンプルで選択できる項目です。すべての番地の読み書きを保証するものではありません。接続先PLCの使用可能範囲と、書き込み対象がPLCプログラムに与える影響を確認して使用してください。
