# STAMPLCからFX5UのD100を読み、LCDに表示する

M5Stack STAMPLCと三菱電機FX5Uを、本体内蔵のRS-485で接続する記事用サンプルです。STAMPLCから読み取り要求を送り、FX5UのD100を1ワード取得してLCDに表示します。読み取りが終わるたびに1秒待ち、同じ処理を繰り返します。

MCプロトコルには指定の[mcprotocol-serial-cpp](https://registry.platformio.org/libraries/fa-yoshinobu/mcprotocol-serial-cpp)、本体の初期化とLCDには[M5Stack公式M5StamPLC](https://github.com/m5stack/M5StamPLC)を使います。

PlatformIO公開版 `fa-yoshinobu/mcprotocol-serial-cpp@4.2.1` を使用します。ローカルのライブラリリポジトリは不要です。

配線・FX5Uの設定・使用ライブラリは[共通README](../README.md)を参照してください。

## LCDで結果を見る

D100が1234の場合、LCDは次のような内容になります。以下は表示内容の例で、実機写真ではありません。

```text
D100:1234
```

LCDには`D100:1234`のように1行で表示します。デバイス名と数値は同じフォント・3倍サイズです。数字は**符号付き16bit整数**として解釈し、`D100:-32768`も横幅に収まります。USBログにも同じ符号付き整数を表示します。D100は1ワード＝16bitなので、32bit整数や浮動小数点数としての読み取りではありません。

WORD・ビット・DWORD・float・ランダム・複数ブロックの読み書きは、[MCプロトコル読み書きデモ](../STAMPLC_MC_PROTOCOL_DEMO/README.md)を参照してください。書き込みを含むため、実行前に対象デバイスの説明を確認してください。

正常時は読み取り時間＋1秒ごとに画面を更新します。通信エラー時は古い値を消し、LCDに`COMM Error`だけを表示します。3秒後にUARTを再初期化してD100の読み取りを再開し、成功したときに数値表示へ戻ります。復旧待ち中もM5の処理を継続します。USBログには詳しいエラーが出ます。

RGB LEDは読み取り成功時に緑を約150ms点灯し、その後消灯します。通信異常時は赤を点灯し、次の読み取り成功で緑に切り替わります。このデモは読み取り専用なので青は使用しません。LEDは通信結果を示します。

## コードを上から読む

### M5公式ライブラリで本体とLCDを初期化する

`M5StamPLC.begin()`で本体を初期化し、`M5StamPLC.Display`でLCDを操作します。LCD用の低レベルドライバを自作する必要はありません。日本語の説明はソースコメントと本記事に置き、LCDは標準フォントで読める英数字を使用しています。

`enableModbusSlave = false`は、公式ライブラリのModbus機能と今回のMC通信が同じUARTを使わないようにする設定です。今回の通信方式はMCプロトコルです。

### RS-485の送受信方向を設定する

公式ライブラリのピン定義を使い、RX＝GPIO39、TX＝GPIO0、DIR＝GPIO46を指定します。`Esp32UartClient plc(1)`がUART1を管理するため、デモ側で`HardwareSerial`や`Serial1.begin()`を追加する必要はありません。

RS-485の2線式では、同じ線を使って交互に送受信します。`Esp32UartConfig`へピン・速度・パリティを設定し、`direction = Esp32Direction::Rs485Rts`と`rts_pin = DIR_PIN`でUARTドライバによるDIR切り替えを選びます。`plc.begin(uart, protocol)`がUARTとMC通信の設定を初期化します。戻り値が成功でも、PLCからの応答確認は読み取り時に行われます。

### FX5U向けの通信条件を渡す

`ProtocolConfig::c4_binary()`で形式5を選び、`PlcProfile::MelsecIqF`でFX5U用のコマンド形式を選択します。`SumCheckMode::Enabled`はサムチェックありです。`HostStationRoute{}`は直接接続先を対象とし、このサンプルではFX5Uの局番を0に合わせます。

`TimeoutConfig{3000, 250}`は、全体の応答待ち上限が3000ms、応答の途中でデータが途切れた場合の待ち時間が250msという意味です。

### D100を読む → 結果を確認する → 表示する

読み取りは非同期で開始します。受信先は完了まで保持するためグローバル変数です。

```cpp
int16_t d100 = 0;
// loop()で、通信中でなく次回時刻になったときだけ呼ぶ
check(plc.async_read_word({DeviceCode::D, 100}, d100, onRead));
```

`async_read_word()`は要求を開始して戻ります。`loop()`で`plc.update()`を呼ぶたびに送受信・応答解析・タイムアウト処理が進み、完了時に`onRead()`が呼ばれます。符号変換はライブラリ内で行い、成功した値をLCDへ表示します。

応答待ちでも`M5StamPLC.update()`を続けます。1秒の読み取り間隔と3秒の復旧待ちは`millis()`の時刻差で管理します。通信専用タスク・キュー・FreeRTOSタイマーは使用しません。LCD描画は同じloop内の同期処理で、通信の応答待ちだけを非同期にしています。末尾の`delay(1)`でRTOSへ実行機会を渡します。[ライブラリの公開ページ](https://registry.platformio.org/libraries/fa-yoshinobu/mcprotocol-serial-cpp)

### 読み取り専用の自動復帰

デモはエラー後に3秒待ち、`recover()`でUARTとプロトコルを再初期化します。初回のUART初期化に失敗した場合は`begin()`から再試行します。無応答が続けば、応答待ち最大3秒＋再試行待ち3秒を繰り返します。

3秒はデモの再試行間隔であり、PLCの最大応答時間の保証値ではありません。形式5には遅延応答を次の応答と区別できない場合があり、UART再初期化だけで線上の遅延応答が消えるわけではありません。本例は1対1接続で同じD100だけを繰り返し読む表示用途に限定し、厳密な値の取得時刻を保証しません。書き込みや要求番地を切り替える用途へ、この復旧方針をそのまま流用しないでください。

`static_cast<int32_t>(millis() - nextRead) >= 0`で期限を判定します。時刻差が約24.8日未満で定期的に判定する限り、約49.7日でのmillisの周回をまたいでも動作します。

## 表示されないとき

| 症状 | 確認すること |
| --- | --- |
| 約3秒後にエラーになる | FX5UがMCプロトコルか、局番0か、配線・電源・送受信の短絡が正しいか |
| 受信形式／サムチェックのエラー | 両側が形式5・19200・8E1・サムチェックありか |
| PLCエラーコードが出る | USBログのPLCコードと三菱電機マニュアルのエラー一覧を照合する |
| 読めるが常に0 | GX Works3でもD100が0でないか、ラダーが上書きしていないか |
| 負の値が表示される | `int16_t`を指定して符号付きで読み取っています。USBログも同じ値です |
| 書き込み後も前の動作のまま | Upload対象のCOMポートと書き込み結果、RESET後の起動を確認する |

## 使用ライブラリとメモリ使用量

PlatformIO公開版4.2.1を使用したビルドで確認した使用量です。ソースや依存ライブラリを変更すると増減します。

| 項目 | 使用量 |
| --- | ---: |
| 静的RAM | 35,592バイト（10.9%） |
| プログラムサイズ | 589,873バイト（17.6%） |

要求フレーム768・応答フレーム768・要求データ384バイトを`build_flags`で指定し、標準8KBのloopスタックで動かしています。バッファ容量はD100を1ワード読む用途に合わせています。

動的に確保されるUARTバッファや実行中のスタックは、この静的RAMの値には含まれません。

| 依存関係 | ビルド確認した版 |
| --- | --- |
| Espressif32 / Arduino-ESP32 | 6.12.0 / 2.0.17 |
| mcprotocol-serial-cpp | PlatformIO公開版 4.2.1 |
| M5StamPLC | 1.2.0（PlatformIO配布版） |
| M5Unified | 0.2.13 |
| M5GFX | 0.2.28 |

`platformio.ini`では上表の版を指定しています。追加の`string_view`互換性ヘッダーは不要です。
